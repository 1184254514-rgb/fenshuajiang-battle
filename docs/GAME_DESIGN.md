# 粉刷匠大作战：玩法设计草案

本项目由爱好者发起，旨在通过自主开发复刻已下架的《粉刷匠大作战》，属于非官方项目。

本文是复刻原型的拟议设计，并非已核实的原版完整规则。各项机制需结合原版资料、玩家反馈与试玩结果逐步确认，尚待代码实现与验证。

## 体验目标

让玩家在短时间内理解“把更多地面刷成自己的颜色”的目标，并通过移动路线、覆盖时机和颜料管理影响战局。

## 核心循环

观察地图 → 选择路线 → 移动涂色 → 争夺覆盖 → 补充颜料 → 再次争夺 → 时间结束后结算。

## 首个原型的范围

先验证单机涂色占地，不预设账号系统、在线匹配或商业化功能。首个原型需包含一张地图、玩家移动、地面涂色、覆盖统计、倒计时、结算与重开。

技术栈、视角、操作设备及地图尺寸待选型后确定。

## 规则草案

- 地图由可涂色地面与不可涂色障碍构成。
- 可涂色地面具有唯一归属：空白或某个阵营。
- 新颜色覆盖旧颜色后，区域归属与双方面积统计同步更新。
- 占领率 = 阵营当前占领的有效地面面积 ÷ 地图全部可涂色面积。
- 对局时间结束时，以最终占领率判断胜负；相同则判为平局。
- 对局时长、刷子范围、移动速度、消耗与恢复速率均属于待测试参数。
- 颜料不足时限制涂色；具体补给条件在手感验证阶段确定。

## 操作与反馈

- 移动输入与相机表现应保持一致，避免遮挡关键争夺区域。
- 涂色范围与实际命中地面应一致。
- 界面展示剩余时间、占领率与当前颜料状态。
- 区域覆盖变化应及时反馈；颜色之外还应探索图案或标识辅助辨认。
- 结算展示胜负、最终占领率与重新开始入口。

## 地图方向

地图需要同时具备可争夺的中心区域与能够绕行的侧翼路线。障碍应创造选择，减少单一路线长期压制的情况。先用简单几何地图验证规则，再制作正式场景。

## 原型验收目标

- 玩家可以移动，障碍能正确阻挡移动。
- 涂色只影响有效地面。
- 覆盖同一区域不会重复计分，覆盖对方区域会同步更新归属。
- 空白地面存在时，所有阵营占领率之和可以小于 100%；任何情况下都不能超过 100%。
- 倒计时结束后停止对局计分，并按最终占领率结算。
- 重新开始后，地图归属、资源、计时和统计均恢复初始状态。

## 后续待定事项

1. 采用何种引擎、目标平台与视角。
2. 是否加入攻击、受击、淘汰和重生机制。
3. 个人竞技与团队对抗的优先顺序。
4. 是否需要 AI 对手与联网服务。
5. 联网时的状态同步、服务端计分、身份认证和防作弊方案。

如引入账号系统，需要另行记录密码哈希、服务端密钥、令牌签发与验证、过期、刷新和退出策略。目前这些机制均未实现。
