# 复刻差异与验收清单

核对日期：2026-10-25。范围：Windows 离线版本、当前四分钟比赛。Android、网络和其他比赛模式不在本清单验收范围内。现有联网代码保留，不代表本轮已经验证。

## 判定方式

- **已有原版证据**：原运行参考、包内代码/资源、配置表支持某个具体结论。不能因此把整个系统标成完成。
- **本地适配**：为离线运行或用户指定规则建立的行为。必须与原版证据分开记录。
- **证据不足**：缺原版运行对照、资源、明确调用关系或服务器实现，暂时不能认定一致。

验收状态独立于证据分类。“代码测试通过”说明当前实现符合测试条件；只有原版参考与本地结果在同等条件下吻合，才能验收对应的原版一致性。截图中的测试场景与测试注入数据必须注明。

## 用户指定改动

默认四分钟；活着的所有角色颜色不同；所有角色与自己的旧线交叉时，删除交叉点之后的线、保留此前路线，从交叉点继续；技能配置从大厅底部“技能”进入；保留隐藏 F8 策划入口。这些作为固定验收条件，不要求改回原版。

## 本轮：碰撞与死亡事件（v0.7.1）

### D-01：自己交叉回退

用户指定规则，不标为原版规则。导演角色与 AI 共用 `SceneSim.enter_node` / `rollback_trail`。验收要点：保留交叉格、删除其后所有格、不获得圈地、不死亡、保留底层领地，之后可继续画线。既有路线回归用于验证这些条件。

### D-02：圈地与远处路线死亡的证据冲突

此前本地版本曾把被圈内路线的主人直接杀死，后改为圈地保留外来活线路。后者可以避免未接触路线时被远程判死，但**目前只能标为本地适配，不能声称它就是原版规则**。

新核查的原生证据：`CManor::AddManorUnit`（Thumb 入口 `0x33e424`，函数长度 488）在 `0x33e574` / `0x33e5ec` 虚调用后分别于 `0x33e578` / `0x33e5f0` 调用 `CPlayer::Die`（`0x3418f4`）。其前置条件涉及 peer unit、玩家归属字段与被添加格坐标。2026-10-25 已继续确认后半段是旧领地登记角色的逻辑头部位置检查，现已补齐该窄条件；v0.7.3 继续恢复前半段在当前单活路线中的出发连接条件；原版多条旧线/桥接线仍未完整映射。因此不能据此判定“任意圈到路线都应该死亡”，也不能断言“原版圈地绝不导致死亡”。原生反汇编来自桌面 `mod-work/gpt/disasm_moveA.txt`，原始包摘要见 `APK差异核对-2026-10-21.md`。

后续验收：完成多条旧线、无填充回家桥接线及拆分重接的映射，或用原版可运行画面测试“仅圈住外来线”“占到对手头部”“占完对手领地”三种独立情形，再调整离线实现。当前保留已发布的路线保留适配，不在证据不足时来回猜改规则。

### D-03：远处实际切线与死亡说明

对手可以离本人头部很远，同时实际接触本人留在远处的活线路。只观察头部附近没有其他角色，不能排除实际切线。本轮记录死亡前的原因、对手、时间、位置、路线长度、剩余领地、双方头部距离及对手到路线格中心的最近距离，保存于用户数据目录 `last_death.json`。这是排错记录，不是原版功能。

复用原 `CTyroWnd` / `zhishi_duihuakuang2` 显示切线、领地消失或护盾原因、对手和重生倒计时。缺少原因的事件明确显示“死亡原因待核对”，不默认归为领地消失。提示文字和三秒倒计时是本地适配；没有新建另一套局内面板。

本轮自动化验收包括：实际远处路线接触、与记录一致的提示、重复死亡拒绝、三秒后恢复、未知原因不误标、不同原因提示与返回大厅。截图取自受控注入场景，不是原版运行截图。原版视觉逐帧一致性仍未验收。

验证结果：死亡流程新增长帧检查后共 21 项；路线回归 54 项、技能回归 115 项、常规比赛界面流程 91 项、定时器调度 7 项通过。独立 Windows 离线 EXE 的死亡流程 21 项、实际输入及比赛流程 91 项通过；已查看该 EXE 渲染的提示框截图，移除了重复的自定义重生文字。截图见 `images/death-audit-v0.7.1.png`；原包缺资源、部分材质/模型告警仍在，测试通过不代表这些差异已消除。

独立 EXE 的完整 240000ms 模拟通过：10 人固定名单、13 次死亡/重生、10 名角色均有技能使用，期间检查路线归属与最终结算。模拟结果受测试初始条件影响，死亡次数不是还原准确性的评分；本轮没有运行网络或其他比赛模式验收。

### D-04：长帧定时器验证

验证期间发现可复现的调度缺陷：定时器回调停止再注册自己时，原适配层会把它追加到正在遍历的列表。一帧时间达到其间隔时，同一轮可反复运行新注册项。现按固定队列快照处理，按注册代次拒绝本轮已经重启的项，并在下一轮去重；普通周期定时器仍保留原有最多四次的补偿边界。这是 Godot/Lua 适配修正，不是从原 APK 恢复的定时器实现。

定时器 7 项回归覆盖长帧重启、新建延后、下一轮不重复、正常补偿及停止；独立 EXE 的死亡核对入口另注入 10000ms 长帧，确认能继续完成整条流程。核对入口为命令行 `-- --verify-death-audit`，正常启动不进入测试，没有增加可见调试按钮。

## 本轮：路线出发连接（v0.7.3）

详见 [圈地路线连接核对-2026-10-25.md](圈地路线连接核对-2026-10-25.md)。已交叉核对 `ConnectUnit`、`RemoveConnect`、`AddUnit`、离家/回家、`AddRectangle/CheckLines` 和 `AddManorUnit`：`+0x12` 是跨层连接，`+0x11` 才是同层线段；当前活路线的出发格被抢时触发路线角色死亡，不能替换为任意圈内路线或相邻路线死亡。

本轮实现出发连接的建立、抢占与双端清理；角色头部可在圈外。保留上一轮占到脚下格的条件、用户自交回退和动画回调修复。状态为“已有原版证据 / 已实现待对照”；没有原版实机同条件画面对照。原版多条旧线、桥接线和拆分重接仍缺完整本地对象模型，不把当前单活路线适配升级为整个碰撞系统已验收。

本轮发布只包含活路线出发连接及占格死亡条件、死亡事件/提示、差异清单及相关回归，不将开发区大厅、教学、材质、每日任务等未完成验收的改动混入运行包。它是阶段性核对版本，不能称为“完整复刻”或“完美还原”。
