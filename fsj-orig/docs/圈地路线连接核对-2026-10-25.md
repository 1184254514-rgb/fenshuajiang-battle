# 圈地与外来路线：跨层连接核对

日期：2026-10-25。版本：v0.7.3-peer-capture。上轮基线：`11cf036` / v0.7.2。
范围：Windows 离线、当前四分钟模式；没有推进 Android、网络或其他模式。

## 本轮结论

**抢占仍与外来活路线相连的领地出发格，会通过原生 peer 分支杀死路线所属角色，即使头部在圈外。圈住路线中段或单纯与路线相邻，不会自动产生该连接。**

原版 `+0x12` 是不同层之间的双向连接，不是“这里有路线”的标记；同层相邻线段使用的是 `+0x11`。本轮恢复当前每个角色单条活路线的出发连接、抢占判定和清理。

- 证据分类：出发连接及 `AddManorUnit` peer 分支为 **已有原版证据**。
- 实现状态：上述分支 **已实现待对照**。新代码与实际运行已验证，已查看本地历史实机参考视频，但其来源/版本及关键连接状态未核实，尚无同条件可判定的原版画面对照。
- **本地适配**：当前单条活路线模型、全局边界泛洪圈地、三秒重生、全部领地耗尽死亡和提示文案继续保留。
- **证据不足 / 未完整映射**：原版多条保留旧线、跨孤立领地的桥接线、`BreakOn` 拆分后重接路线及无填充回家时留下的另一端连接。没有把这些情形冒充成本轮已完成。

### peer 死亡分支与中段路线

`CManor::AddManorUnit` `0x33e424` 首先在 `0x33e45a..0x33e460` 判断格子是否已经属于自己；是则直接返回。

需要转移格子时，`0x33e46c..0x33e57e` 读取该 **领地 unit** 的 `+0x12`，按 `1,2,4,8` 遍历连接，经 `GetPeerUnit` 得到相邻 **line unit**，再通过其 parent 的 `GetPlayer` 得到路线角色。`0x33e55a..0x33e568` 比较其 `player+0x124` 与占格行为玩家的领地指针；不同领地时，`0x33e574/0x33e578` 调用 `KilledByPlayer(actor,false,false)` 及 `Die()`。虚表解析依据与上一轮相同。

因此判断对象是“这个被抢格记录着的真实连接”，不是任意四邻路线，更不是多边形内所有路线。

继续核查的 `CManor::AddRectangle` `0x33e828` 会逐格占领后调用 `CheckLines` `0x33e7d0`；后者先比较 line 所属 manor 与当前 manor，只移除属于当前 manor 的旧线。该调用没有为外来中段增加一条普遍死亡规则。当前保留中段 line 层，不以重新推测的面积或距离替换连接判定。

原版 `EnterHome` 无填充路径和 `BreakOn` `0x33f21c` 还会重接、拆分多条旧线。这些调用已找到，但当前单活路线存储没有相应完整对象结构；本轮不扩大“出发格”结论去覆盖全部旧线端点。

## 实现与生命周期

新增 `lua/natives/scene_connections.lua`，记录已经通过真实离开领地动作建立的连接：领地格、首线格、双方方向与玩家身份。普通路线追加、空间相邻和被圈入都不会生成连接。

- 正常移动将实际跨格前的位置传给原有 `enter_node` 适配链；只有从自家格进入首线格才建立连接。
- 占格先处理 peer 分支，再重新读取旧归属。死亡清理可能已移除旧领地，不能再用过期计数扣一次面积。
- 死亡、正常闭合、固化和新生命启动均清除两端记录；自交回退保留首段时保留原连接。
- 判定前校验角色存活、首线格、实际 line 层归属、旧领地归属和双端身份，防止旧生命记录或单纯相邻格误杀。
- 使用独立 `anchor` 死亡原因，复用原提示框显示“路线连接点被圈占”。死亡记录增加 `peerLineCell/peerDirection`，并保留被占格、原归属与圈地/固化来源。
- 保留上轮占到脚下领地的 `capture`、实际切线的 `trail` 和本地全部领地耗尽的 `territory`，没有把所有远处死亡都标成同一原因。

原 Shell Lua、GUI JSON、图像、模型和原动画没有修改。未提交的大厅、教学及材质开发改动未纳入本轮发行包。
