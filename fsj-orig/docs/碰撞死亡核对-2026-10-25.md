# 碰撞与死亡：被占脚下领地的条件核对

日期：2026-10-25。目标版本：v0.7.2-capture-collision。
范围：Windows 离线四分钟比赛。没有开发 Android、网络或其他比赛模式。

## 本轮结论与边界

原生代码支持一个此前漏掉的条件：**占走另一块领地的格子时，如果那块领地登记的有效角色正位于该格，就调用被击杀与死亡流程，即使它还有其他领地。**

本轮只把这个条件映射到当前每个角色独立领地的离线实现。不是“所有在圈内的头部都会死亡”，也不是“圈内任何路线都不致死”。原包的 peer-unit 路线连接分支尚未完整映射到本地网格；继续保留已发布的远处活线路保留策略，并标为本地适配。

证据分类：上述占格条件为**已有原版证据**；当前全领地耗尽死亡、三秒重生、护盾接触距离、远处活线路保留和提示文案为**本地适配**；原版完整圈地/路线连接效果及护盾范围仍为**证据不足**。

实现状态：占格分支**已实现待对照**。本地运行验证通过后仍不等于原版运行画面的同条件验收；本轮没有原版实际运行录像或在线比赛可作画面对照。

## 原包与字段证据

读取的是原 APK 的 `lib/armeabi-v7a/libShellClient.so`。已逐字节确认独立解出的 SO 与 APK 成员一致。

- APK SHA-256：`fe6c45a7196145293f8638c7f88fc253acb39054267374c8e488120d19480db4`。
- SO SHA-256：`07e2461bb7273361415966c857da58c4d7e4774e99e62cd79961847604396aa7`。
- 当前原包位置：桌面 `game/gpt-collab-gamedev/mod-work/orig/fsj-1.3.3.apk`。
- 反汇编工具：同目录上层的 `tools/disasm.py`，使用 ELF 符号与 Capstone Thumb 解码；此前输出为 `gpt/disasm_moveA.txt`。原 APK 和 SO 不加入源码仓库。

字段与调用链交叉核对：

| 原地址/结构 | 可以支持的结论 |
|---|---|
| `CManor::AddPlayer` `0x33df4a`，从 manor `+0x3c` 建立集合、节点 `+0x10` 保存玩家指针 | `AddManorUnit` 后半段遍历的是旧领地登记的玩家集合，而不是区域内所有物体 |
| `CPlayer::OnSetPosition` `0x343488`；`0x34369e..0x3436bc` 更新 `player+0x16c/+0x16e` | 后续比较的打包两个 short 是玩家逻辑坐标；不是像素位置或路线长度 |
| `CManor::AddManorUnit` `0x33e424`，488 字节；`0x33e45a..0x33e460` | 若格子已属本领地，直接返回；不重复触发抢占死亡 |
| `0x33e580..0x33e5b0` | 旧归属存在时，先 `RemoveUnit`，再复制其玩家集合 |
| `0x33e5b8..0x33e5dc` | 只检查非空、`CCharacter::IsValid` 成功，并且两个逻辑坐标均等于当前占格坐标的玩家 |
| `0x33e5de..0x33e5f0` | 读取新领地 `+0x50` 的行为玩家，传入两个 false，先虚调用被击杀回调，再 `CPlayer::Die` |
| `_ZTV7CPlayer` `0x5436c8`、`_ZTV13CPlayerClient` `0x54aae8` | 对象 vptr 指向符号起点 `+8`；dispatch `+0x58` 对应表项 `+0x60`，分别为 `KilledByPlayer` `0x342054` / `0x3965ac` |
| `CManorLine::Concrete` `0x33e778` | 把线的玩家写到 manor `+0x50`，逐线格虚调用 `AddManorUnit`；固化应复用同一占格条件 |

因此，伪代码的已证实部分为：

```text
if unit.previousManor exists and unit.previousManor != capturingManor:
    previousManor.RemoveUnit(unit)
    for player in copy(previousManor.registeredPlayers):
        if player valid and player.logicalPosition == unit.logicalPosition:
            player.KilledByPlayer(capturingManor.actor, false, false)
            player.Die()
capturingManor adds unit
```

省略的 peer-unit 分支不能视为“不存在”。该分支在 `0x33e46c..0x33e57e` 检查 unit `+0x12` 的四方向连接标记，调用 `GetPeerUnit`，通过其 parent 的 `GetPlayer` 得到目标，比较双方 `player+0x124` 领地指针；不同领地时也会调用被击杀与死亡。`GetPeerUnit` `0x33dafc`、scene 版本 `0x3366c8` 会在领地/路线层之间取相邻记录。**当前适配器没有复原连接标记的建立、更新及全部几何对应关系，不能把它等同于“圈内任意路线格”。**这是与远处活线路保留策略仍未关闭的差异。

## 实际修改

- `SceneSim.claim_cell` 统一圈地和固化的领地转移，在旧领地失去该格后检查其角色逻辑位置；命中时使用 `capture` 原因，清理剩余领地和路线，再把当前格交给圈地者。
- 新增原因复用原 `CTyroWnd` 提示框，显示“脚下领地被圈占”；不会误标为全部领地耗尽。
- 对应死亡记录增加 `contactCell`、`previousOwner`、`source`（`loop` 或 `concrete`），记录实际触发格和调用路径。
- 护盾只继续拦截现有 `body` 原因，不额外赋予未证实的占格免死能力。
- 实际快速死亡/返回大厅过程中发现旧 `fly_die` 延迟回调捕获了已释放节点，检查通过仍会报引擎错误。改为只绑定角色 ID、节点实例 ID 与本次死亡序号，在回调时重新确认当前角色；旧场景/旧死亡回调不能隐藏新一局或重生后的角色。此项是渲染适配修正，未更换原动画。
- 未修改原 `ShellClientLua`、`ShellCommonLua`、GUI JSON、模型或贴图。大厅/教学开发区改动未纳入本轮运行包。

## 六类情形与状态

| 情形 | 本轮处理 | 证据分类 / 状态 |
|---|---|---|
| 对手远离头部、实际碰到远处路线 | 仍按实际路线接触死亡，与圈地原因分开 | 本地路径已实现；完整原版接触范围待对照 |
| 仅把外来活线路圈入，头部留在其他地方 | 保留路线，之后真正碰线仍能切断 | 本地适配；peer 分支映射证据不足 |
| 占到对手正站着的自家领地格，仍有远处领地 | 本轮补齐 `capture`；同一条件用于固化 | 已有原版证据；已实现待对照 |
| 占尽全部领地、头部在外 | 保留当前 `territory` 处理，独立标注 | 本地适配；原版完整生存条件待核对 |
| 普通头部接触 / 护盾接触 | 保留现有护盾处理；普通接触不新增死亡 | 当前距离为本地适配；原版范围证据不足 |
| 重生、无接触移动、自交回退 | 验证清理与重生、独立回退测试，不新增免死 | 三秒重生为本地适配；回退为用户指定规则 |

## 验证记录

受控场景使用真实离线宿主、原 UI 和原玩家回调，主动设置棋盘与角色位置；不是原版游戏运行录像。新检查在 v0.7.1 源码快照中确认了占格条件漏判，再对修改后的源码与导出的独立 EXE 验证。

运行检查入口：`-- --verify-collision-rules`。截图参数：`--shot=<绝对路径.png>`。另沿用 `--verify-death-audit`、`--verify-timed-flow`、`--verify-round-soak`。

最终验证结果：

- 新条件源码检查 34 项通过；独立 Windows 离线 EXE 的同一检查加截图共 35 项通过，包含真实方向键闭合路线、圈地/固化、非自家格不误判、护盾、完整领地耗尽、路线接触、重生、重复事件拒绝及保存的触发格。
- 源码路线回归 54 项、技能回归 115 项、比赛回归 66 项通过。路线测试使用只加载 natives 的既有入口；技能/比赛测试使用完整原脚本入口。
- 独立 EXE 既有死亡检查 19 项通过（无窗口模式，未执行其两项截图相关检查）；实际窗口的常规比赛、键鼠输入、技能升级、结算与页面操作 99 项通过，包含 8 张截图。
